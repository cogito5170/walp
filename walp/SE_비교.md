# WALP 와 SE 에이전트 — 무엇이 같고 무엇이 다른가

SE 는 **LLM 이 생성하고 LLM 이 아닌 것이 심판하는** 저장소다(README: "생성자와 심판을 분리하고 심판은
LLM 이 아니다"). WALP 는 **생성자 자리에서도 LLM 을 뺀다.** 그래서 둘은 같은 뼈대의 두 끝이다.

## 모듈 대응

| WALP 모듈 | SE 에 이미 있는 것 | 같은 점 | 다른 점 |
|---|---|---|---|
| A. 명령 해석(파서+개념 사전) | Gemini ReAct 에이전트가 자연어를 받음 · `dispatch.앞세울것` 의 정규식 표 | 둘 다 '어느 일인가' 를 먼저 가른다 | SE 는 LLM 이 해석하고 표는 좁은 흰 목록만 가로챈다. WALP 는 **전부** 규칙으로 하고, 모르면 거부·되묻기(held-out 69%, 잘못 실행 0) |
| B. 목표·제약 관리 | `plan/`·`intent/` 의 목표 원장(승인은 사람) | 목표를 구조로 들고 승인 전 실행 금지 | WALP 목표는 비트마스크 몇 칸 — SE 목표는 자연어 문서 |
| C. 사례 검색 | `agent_memory.search_memory`(낱말 겹침 점수) · `graph/` 깃발 색인 | 둘 다 임베딩 없이 색인·겹침으로 찾는다 | WALP 사례는 정수 칸 구조(환경·목표·결과) — 그리고 **해로울 수 있음을 쟀다**(RESULTS §2) |
| C. 계획 | `orchestrator/`(LLM 플래너가 DAG 로 쪼갬 → 검증기 통과만 채택) | 후보를 만들고 검증된 것만 쓴다 | WALP 는 깊이 3·노드 100 의 제한 탐색 — 계획 자체가 결정론 |
| C. 정책 학습 + 검증기 | `self_challenge.py`: 진단 → RED(사고 커밋에서 실패)·GREEN(현재 통과) → `gates/` 승격 | **같은 원리다** — 제안과 승인을 가르고, 두 번의 실행 결과가 승인의 근거 | SE 는 **코드 게이트**를 승격한다. WALP 는 **정책 파라미터·규칙 간선**을 승격한다. 그리고 WALP 는 무검증 갱신과 나란히 재서 검증의 값과 대가를 숫자로 냈다(RESULTS §3·§4) |
| D. 안전 감독 | `gatekeeper.py` 게이트 19개(커밋 직전 강제) · `toolgate.py` · `fw/safety.c` | 제안이 아무리 좋아도 마지막 문을 못 지나면 안 된다 | SE 의 문은 **커밋** 앞에 있다. WALP 의 문은 **행동 하나하나** 앞에 있다 |
| D. 결정 기록·재생 | 원장들(`*/ledger.jsonl`), `fw/` replay | 결정마다 근거를 남긴다 | WALP 는 규칙 ID·증거 ID·정책 버전·사례 ID 를 한 줄에 — 기록만으로 재생해 40/40 같은 결정열 |
| E. 플랫폼 어댑터 | `fw/`(C99 SAR executive) · `policy_core/`(OS 독립 C) | 코어는 센서·OS 를 모른다 | `fw/` 는 C99 · 도메인 프로파일. WALP 는 C++17 · 인터페이스는 명세의 가상 함수 |
| LoopAct(고리 = 최상위 행동) | Gemini 에이전트의 ReAct 고리 · 서브에이전트 고리 | 바퀴마다 도구를 부르고 관측을 원장에 쌓는다 | SE 의 고리는 **모델이 한 바퀴 더 돌지 정한다.** WALP 의 고리는 **정책이 정한다**(ANSWER/LOOP/REFUSE, 예산·멈춤 규칙이 코드). 대신 도구가 구조화된 결과를 줘야만 돈다 |

## 한 줄로

**SE 에이전트는 "생성은 유연하게(LLM), 판정은 딱딱하게(코드)" 이고, WALP 는 "둘 다 딱딱하게" 다.**
그 대가를 RESULTS 가 쟀다: 딱딱한 생성은 **틀리게 실행하지 않는 대신 많이 거부한다**(봉인 평가 문장 — 사람이 아니라 다른 언어모델이
쓴 것 — 의 31~37% 를 못 받음. 진짜 사람 말투의 수는 `!walp 결과` 에서만 나온다). SE 가 LLM 을 생성자 자리에 두는 이유가 그 수다.

## WALP 가 SE 에 돌려줄 수 있는 것

1. **검증기의 값과 대가를 재는 틀.** `self_challenge` 는 승격만 하고 '승격 안 했으면 어땠나' 를 안 잰다.
   WALP 의 E3/E4 처럼 무검증 대조군을 붙이면 게이트가 막은 것 중 **좋은 변경**이 얼마나 되는지 알 수 있다.
2. **LoopAct 의 멈춤 규칙과 증거 상한.** 연구형 서브에이전트가 WebFetch 가 막혔을 때 스스로 모든 인용을
   [조각] 으로 두었던 것(2026-09-29 실측)을, WALP 는 **도구 상한으로 강제**한다 — 모델의 정직에 기대지 않는다.
   G022(논문 인용 수준 원장)와 같은 원리를 고리 안쪽으로 옮긴 것이다.
3. **사용성 원장.** 고정 명령이 사람 말을 얼마나 못 알아듣는지(`!walp 결과` 의 '사전에 없던 말 상위') —
   `dispatch` 표에도 같은 계기를 달 수 있다.
