## 재검증 중 나온 측정 결함

1. **`trace_stats` 의 `git` 은 명령에 git 이라는 낱말만 있으면 루틴이다.** 〔계산〕 이 분석 세션에서 `git` 으로 분류된
   10턴이 **전부** 읽기 전용(status · log · ls-remote · grep)이었는데, 루틴 56% · 연쇄 덧턴 32% 로 나왔다. 주 세션의
   "루틴 40%" · "연쇄 덧턴 13.8%" 는 **상한**이고, 상태를 바꾼 git 이 얼마였는지는 모른다.
2. **P3 는 정의상 늘 일치다.** 재생에서 제안 = 일치라 79/79 는 아무것도 검증하지 않는다.
3. **P2 는 겹치는 커밋 창을 두 번 셀 수 있다**(12턴 창 안 연속 커밋이 각자 같은 구간을 더한다). 얼마나 그랬는지는 원시
   로그 없이 확인 못 했다〔가설〕.
4. **분모가 문서마다 다르다.** 설계.md 1,454턴 · 611M · 덧턴 181 / JSON 1,456턴 · 612.1M · 182 / 재생 1,485턴 · 629.1M
   (더 늦은 스냅샷). 설계.md "루틴 40~45%" 의 45% 를 낸 두 번째 분류 방식은 저장소에 없어 재현 못 했다.
5. **`그림자_실제.json` 은 세션 총 토큰이 없어** 아낀 비중을 못 낸다. 제안 4건뿐(P1 2/2 의 Wilson 95% 하한 34%).

## 7. 측정 불가 항목과 로그 수집의 한계

- 주 세션 원시 JSONL · 실제 그림자 원장이 저장소에 없다 → 재검증 범위가 집계까지.
- 세션 하나 · 사용자 하나 · 하루. 과제별 성공/실패 표시가 없어 "성공한 과제당 토큰" 을 못 낸다.
- 턴 종류를 첫 도구로만 정한다(한 턴의 여러 도구가 사라진다). 3걸음 패턴은 겹치게 센다.
- 턴마다 맥락이 얼마나 늘었는지(어느 도구 결과가 이후 모든 턴에 다시 읽혔는지)를 안 적는다 → P4 상한을 못 낸다.
