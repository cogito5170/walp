# 사전등록 — P4 출력 예산 (Context & Tool-Output Budgeting)

수를 보기 **전에** 커밋한다. 통합 관문(P1~P3, 2026-10-01)을 통과한 뒤에 시작했다.

## 무엇을 바꾸나

`walp-exec budget-hook` (PostToolUse, Bash 만, 기본 꺼짐): stdout/stderr 가 6,000 자를 넘으면 **머리 40 줄 + 가운데의 오류 · 실패 ·
요약 줄(최대 80) + 꼬리 60 줄**만 모형에 보내고, 전체는 파일로 남겨 경로를 알려 준다(필요하면 모형이 Read 로 본다).
Claude Code 의 `updatedToolOutput` 으로 바꾼다 — Bash 응답과 같은 꼴(dict)이어야 먹는다(실측: 문자열은 조용히 무시된다).
Read · Edit · MCP 출력은 건드리지 않는다.

## 조건 · 과제

- **A** 훅 없음 · **B** 예산 훅. 같은 `claude -p`(CLI 기본 모형), 도구 `Bash Read`, 같은 일회용 저장소(worldplan 사본, 지역 원격)
- 과제 넷 — 큰 도구 출력이 나오는 대표 꼴, 각각 **결정론적 정답 검사**:
  - **T1 검사 실패 찾기**: 검사 하나를 일부러 깨고 "전체 검사를 -v 로 돌려 실패한 검사 이름" → 답에 그 이름
  - **T2 로그 속 오류**: 3,000 줄 로그 가운데의 오류 한 줄 → 답에 그 오류 문구
  - **T3 집계(가운데가 필요한 것)**: `git log --numstat` 으로 가장 많이 바뀐 파일 → 답에 정답 경로(가운데를 잘라 내면 틀리기 쉽다 — 예산의 위험을 일부러 넣었다)
  - **T4 검색 집계**: `grep -rn "def "` 로 함수가 가장 많은 파일 → 답에 정답 경로
- 과제 × 조건마다 **3 번**, 차례는 회마다 섞는다(seed 4)

## 잴 것 — 따로 적는다

새 입력 · 캐시 만들기 · 캐시 읽기 · 출력 토큰, 비용($), 턴 수, 시간, 성공(정답 검사). 출처는 `claude -p` JSON 의 `usage` · `total_cost_usd`.

## 가설 · 결정

- **H1** 입력 쪽 토큰(새 입력 + 캐시 만들기 + 캐시 읽기) 합이 B 에서 줄었다 — 과제마다 3 회 평균의 차, 과제 넷 중 몇에서 줄었나로 적는다(한 수로 합치지 않는다)
- **H2** 성공이 나빠지지 않았다 — 과제마다 B 성공 수 ≥ A 성공 수
- **결정**: H2 가 깨진 과제가 하나라도 있으면 예산을 기본으로 켜지 않는다. 둘 다 서면 "켤 후보" 로 적고 실사용 그림자로 넘긴다
- 3 회는 적다 — 런 간 분산이 크면 "모른다" 로 적는다

## 사소한 설명 — 재서 죽일 것

1. 모형이 스스로 `| tail` 을 붙여 출력이 원래 작았다 → 예산이 실제로 먹은 횟수(원장의 Budget 줄)를 같이 적는다
2. 줄인 대신 전체 파일을 다시 읽어 턴이 늘었다 → 턴 수와 Read 호출을 같이 적는다
3. 절감이 캐시 가격 탓 → 토큰 종류를 나눠 적고 비용도 적는다
