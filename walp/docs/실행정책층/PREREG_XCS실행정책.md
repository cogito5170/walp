# 사전등록 (초안) — XCS+GA 실행 정책, P1 · P2 · P3 위에서, 그림자 모드만

> **초안이다. 확정이 아니다.** 선행조사 `선행조사_XCS실행정책.md` 가 따로 쓰이고 있다(이 문서를 쓰는 동안 읽지 않았다).
> 그 조사가 커밋되고 **사용자에게 먼저 보인 뒤** 이 문서를 다시 읽고 확정한다(CLAUDE.md "짓기 전에 조사한다"). 조사가 더 가까운
> 선행(예: 실행 걸음을 고르는 LCS · 계획 캐시의 학습된 문지기)을 찾으면 기준선을 더하거나 이 실험을 접는다.
> 확정 전에는 **기록기 코드도 짓지 않는다.** 확정되면 이 문서를 **자료를 한 줄도 보기 전에** 커밋한다.

수를 보기 **전에** 고정한다: 조건(특징)을 어떻게 셈하나 · 행동 · 보상 · 기준선 · 자료와 봉인 가르기 · 최소 자료 · 결정 규칙 ·
사소한 설명 · 무효화 조건. 그림자 모드: 정책은 **제안만** 하고 실제 행동은 LLM 이 한다. 아무것도 막지 않는다.

## 왜 이 실험인가 — 지금까지 잰 것에서

- `PREREG_그림자.md`: 손 규칙 P1~P3 은 **아무것도 켜지 않았다.** P1 재생의 틀림 18 중 17 은 대리 상태의 거짓 양성,
  P2 의 방아쇠(commit)는 11% 만 맞았다, P3 의 100% 는 정의상 거의 참이다. 실제 그림자는 제안 4 개 — "잴 만큼 안 나왔다".
  → 손 규칙의 **방아쇠**가 문제다. 방아쇠를 조건에서 배우는 것이 XCS 의 일이다(`설계.md` §4).
- `eval/PREREG_진화효과.md`: XCS 안에서 GA 는 덮기만보다 확실히 낫다(85/0) — 그러나 진화한 XCS 는 NB 에 5/45 로 졌고,
  `PREREG_성장망.md` 의 은닉층은 0~3 개만 자랐다. **"GA 가 덮기만보다 낫다" 는 "쓸 만하다" 가 아니었다.**
  → 이 실험은 GA 의 몫(H2)과 **손 규칙을 이기는가**(H1)를 따로 재고, 둘 다 서야 말한다.
- 저장소 `README.md`: 잡담 앞단은 토큰을 38~44% 줄였지만 섞인 말 60 개 중 9~10 개를 잘못 보내 안전 기준 5% 를 못 넘었다.
  → 이번에는 **아낀 것보다 잘못 자동 실행이 먼저** 판정된다(μ ≫ λ, 아래).

## 0. 불변식 — 이 실험 내내, 결과와 상관없이

1. **P1 자동 재사용은 꺼진 채다.** 이 사전등록의 어떤 결과도 P1 을 켜지 않는다. 켜려면 V2 봉인 A/B 를 새로 사전등록한다.
2. **훅의 표준출력은 비어 있다.** 그림자 훅(`walp-exec shadow-hook` 과 이 실험이 더하는 기록)은 stdout 에 한 바이트도 안 낸다
   (Claude Code 는 UserPromptSubmit 훅의 stdout 을 맥락에 넣는다 — 낸 순간 그림자가 아니다). 오류는 stderr, 종료 코드는 늘 0.
   검사: 훅을 사건 종류마다 돌려 stdout 길이 == 0 을 단언(정상 입력 · 깨진 입력 · 원장 쓰기 실패).
3. **바깥 동작(밀기 · PR · 머지)은 제안뿐이다.** 정책층의 어느 길도 `publish(push=True)` · `merge=True` · `gh pr ...` 을 스스로
   부르지 않는다. 그림자에서는 로컬 걸음도 부르지 않는다(제안을 원장에 적을 뿐).
4. 원장에는 **해시 · 종류 · 수만**. 말 · 명령 · 파일 내용 · 도구 출력은 안 적는다(grep 으로 확인).
5. 정책층이 터지면 아무것도 막지 않는다(`설계.md` §5-4).

## 1. 결정 지점 — "턴 경계"

턴 경계 b = 모형 턴 하나가 끝나고(그 턴의 도구 결과가 다 돌아오고) 다음 모형 턴이 시작되기 전. 사람의 말이 들어온 때
(UserPromptSubmit)도 경계다. 경계마다 정책은 행동 하나를 고른다. 같은 `message.id` 로 나뉜 스트림 조각은 한 턴으로 센다
(`trace_stats.load` · `execpolicy.replay` 와 같은 규칙).

## 2. 조건(특징) — 무엇을, 어디서, 어떻게 셈하나

출처는 둘뿐이다: **(T) Claude Code 추적 JSONL**(`~/.claude/projects/.../<세션>.jsonl`, 경계 b 이전 줄만) ·
**(L) 그림자 원장**(훅이 그 순간 진짜로 잰 것). 경계 b 의 특징은 **b 이전에 생긴 줄만** 쓴다. 특히 **LLM 이 b 다음에 실제로 부른
도구는 특징으로 쓰지 않는다** — 그것이 정답(보상)의 출처라 넣으면 누수다.

XCS 조건은 {0,1,#} 문자열이다. 범주 특징은 원핫, 구간 특징은 아래 고정 경계의 원핫(온도계 아님)으로 비트를 만든다.

| # | 특징 | 값(비트) | 셈하는 법 |
|---|---|---|---|
| F1 | 직전 걸음 종류 | git · PR·머지 · 기다리기 · 검사 돌리기 · 고치기 · 읽기 · 셸 기타 · 하위 에이전트 · 기타 도구 · 답 쓰기(도구 없음) · 사람 말(경계가 UserPromptSubmit) — 11 | (T) b 직전 모형 턴의 **첫** `tool_use` 에 `trace_stats.kind(name, input)` 을 그대로(a2be5b9 판). 도구가 없으면 "답 쓰기" |
| F2 | 결과 판정 | 성공 · 실패 · 직전과 같음 · 없음 — 4 | (T) b 직전 턴의 `tool_result` 들: 하나라도 `is_error: true` 면 실패. 아니면, 결과 글의 `norm_hash` 가 **같은 F1 종류의 바로 앞 결과**와 같으면 "직전과 같음", 아니면 성공. 도구 없음이면 "없음". (L) 에는 결과 해시만 적는다 |
| F3 | 상태 해시가 바뀌었나 | 바뀜 · 안 바뀜 · 모름 — 3 | (L) **진짜** `execpolicy.state_hash(cwd)` 를 PostToolUse · UserPromptSubmit · Stop 마다 원장에 적고, b 의 값과 **직전 사람 말 때의 값**을 비교. git 저장소가 아니거나 원장 줄이 없으면 "모름". **대리(도구 호출 정규식)는 쓰지 않는다** |
| F4 | 걸음 수 | 직전 사람 말 이후 모형 턴 수: 0 · 1 · 2–3 · 4–7 · 8–15 · 16+ — 6 | (T) |
| F5 | 맥락 크기 | b 직전 턴의 `input + cache_creation + cache_read` 토큰: <50k · 50–150k · 150–300k · 300–500k · ≥500k — 5 | (T) usage. 출력 토큰은 안 넣는다 |
| F6 | 레포 특징 | 언어(파이썬 · JS/TS · Rust · Go · 그 밖) 5 · 검사 명령 있음 1 · 원격 있음 1 · 지금 갈래가 기본 갈래 1 — 8 | (L) 세션 첫 사건 때 cwd 에서: 언어 = `detect_test` 와 같은 표지 파일(package.json · Cargo.toml · go.mod · `tests/test_*.py` 또는 pyproject.toml), 검사 = `detect_test(repo) is not None`, 원격 = `git remote` 가 비지 않음, 기본 갈래 = `HEAD` 가 `origin/HEAD` 가 가리키는 갈래와 같음(없으면 main) |
| F7 | 다음 동작의 위험 등급(대리) | 읽기 · 로컬 쓰기 · 바깥 · 되돌릴 수 없음 — 4, 그리고 '밀지 않은 커밋 있음' 1 · '살아 있는 기다림 PID 있음' 1 | 다음 동작은 b 에서 모른다(아는 순간 누수). 그래서 **b 직전 턴의 도구 호출들 가운데 가장 높은 등급**으로 대신한다: 읽기 = F1 읽기 · 답 쓰기 / 로컬 쓰기 = 고치기 · git 의 commit/add/merge(원격 없이) · 셸 편집 / 바깥 = `_PUSH` · `_GHPR` · `is_pr_tool` · 망 도구 / 되돌릴 수 없음 = `--force` · `reset --hard` · `rm -rf` · 브랜치 삭제 · `merge_pull_request`. 덧비트 둘은 (L): `git rev-list --count @{u}..HEAD > 0`, 그리고 기다리는 PID 가 `_alive` 인가 |

비트 수 합: 11 + 4 + 3 + 6 + 5 + 8 + 6 = **43**. 경계 정의 · 구간 경계 · 범주 표는 이 문서가 고정한다. **자료를 본 뒤 바꾸면**
그때까지의 자료는 학습 쪽으로만 쓰고 봉인 시험은 새로 모은다(수정 번호를 붙여 이 문서에 적는다).

추적만 있고 원장이 없는 세션(예: 지난 오프라인 재생)은 F3 · F6 · F7 덧비트가 "모름" 이다. 그런 세션은 **이 실험의 학습에도 시험에도
쓰지 않는다**(아래 §4) — 기록기 배선을 점검하는 개발용으로만.

## 3. 행동 — 다섯, 그리고 어디서 고를 수 있나

| 행동 | 무엇(켰다면) | 고를 수 있는 경계(적용 가능 가림) |
|---|---|---|
| **LLM** | 다음 모형 턴을 그대로 돈다 | 늘 |
| **P1 재사용** | 같은 말 + 같은 상태면 이전 결론을 다시 낸다 | UserPromptSubmit 경계, 그리고 같은 `norm_hash` 의 말을 이 세션에서 전에 받았고 그 말의 Stop 때 상태 해시가 있다(값이 같은지는 F3 가 말한다 — 가림은 '비교할 수 있나' 만 본다) |
| **P2 매크로 제안** | `walp-exec publish` 의 **로컬 걸음**(commit → 깨끗한 워크트리 검사)을 하고, 밀기 · PR · 머지는 **제안 한 줄**로만 | 작업 트리에 변경이 있거나 밀지 않은 커밋이 있다 |
| **P3 이벤트 기다리기** | `walp-exec wait --pid N` — 끝날 때 한 번 깨운다 | 살아 있는 기다림 PID 가 있다(F7 덧비트) |
| **사람에게 묻기** | 모형을 부르지 않고 사람에게 되묻는다 | 늘 |

- 가림은 **필요조건**일 뿐이다(손 규칙의 방아쇠보다 약하다). 가림이 일을 다 하는지는 §7 의 B-가림 기준선이 잰다.
- **바깥 동작은 어떤 행동의 결과로도 자동으로 일어나지 않는다**(§0-3). P2 의 바깥 걸음은 '제안' 으로만 세고, 보상도 그렇게 매긴다.
- 기본은 올림: XCS 의 맞춤 집합이 비거나, 고른 행동의 경험(θ_exp 미만)이 모자라면 **LLM**.

## 4. 보상 — 결정론적 확인만

경계 b 에서 행동 a 의 보상(그림자이므로 "켰다면" 의 반사실을 **관찰된 뒤 결과로** 매긴다):

    r(b, a) = V(b, a) − λ · T(b, a) − μ · W(b, a)
    λ = 1e-7 / 토큰   (평균 턴 419k 토큰 ≈ 0.042)
    μ = 10           (잘못 자동 실행 한 번 = 확인된 성공 열 개를 지운다; 평균 턴 대비 μ/λT ≈ 240)

**V — 확인된 성공(0 또는 1).** 다음 넷만 V 의 근거가 된다. 그 밖(모형이 "됐다" 고 말함, 사람이 아무 말 안 함)은 근거가 아니다.

| 근거 | 어떻게 확인 |
|---|---|
| 진짜 상태 해시 | (L) `state_hash` 가 원장에 적힌 값 |
| 검사 통과 | (L) 검사 명령의 종료 코드 0 — 깨끗한 워크트리에서 돈 것(`publish` 의 그 걸음)이거나, 원장에 `test_rc` 로 적힌 것 |
| `merged == true` | (L) GitHub API · `gh pr view --json state` 를 **훅이 조회해** 적은 값. 모형의 말이 아니다 |
| 프로세스 끝 | (L) 그 PID 에 `_alive` 가 거짓(좀비 포함)이 된 시각 |

행동별 V · T · W (b 다음에 **실제로** 일어난 것으로 매긴다):

| a | V = 1 | T(쓴 토큰) | W = 1(잘못 자동 실행) |
|---|---|---|---|
| LLM | 그 사람 말의 Stop 까지 위 근거 가운데 그 일에 걸린 것이 하나라도 섰다(상태가 바뀌었거나 · 검사 통과 · 머지 · 프로세스 끝). 걸린 것이 없는 일(질의 · 답 쓰기)은 V = 1 로 둔다 — LLM 은 기준이라 성공 판정을 따로 하지 않는다 | b 다음 모형 턴 하나의 실제 토큰 | 0 |
| P1 | 그 말의 Stop 때 진짜 상태 해시 == 제안 때 해시, **그리고** 그 사이 바깥 · 되돌릴 수 없음 등급 호출이 없었다 | 0(재사용은 모형을 안 부른다) | Stop 때 해시가 다르다(재사용했으면 할 일을 빼먹었다) |
| P2 | b 이후 12 턴 안에 원장에 (밀기 후 원격 추적 ref == 그 커밋) **그리고** (`merged == true` 또는 기본 갈래에 바로 밀기)가 있고, 그 사이 고치기가 없다 | b 부터 마지막 발행 걸음 직전까지 모형이 쓴 토큰을 **아낀 것**으로 보고, 매크로 요약 한 줄은 고정 200 토큰 × 그때 맥락 증가 없음으로 친다 | 12 턴 안에 밀기가 **없다**(발행하지 않을 것을 커밋했다) — 로컬 커밋도 사람이 원치 않은 동작이다. 사이에 고치기가 있으면 W=0 · V=0(매크로는 검사에서 멈추고 올렸을 것) |
| P3 | 그 PID 의 끝이 원장에 있고, **기다림 연쇄 사이에 모형의 사람 대상 글(도구 없는 턴의 글 · 진행 보고)이 없었다** | 연쇄의 둘째 기다림 턴부터 끝까지의 토큰을 아낀 것으로 | 연쇄 중간에 사람 대상 진행 보고가 있었다(끝에 한 번만 돌려주면 그 보고를 잃는다), 또는 PID 가 시한(3600 초) 안에 안 끝났다 |
| 묻기 | 0(확인할 근거가 없다) | 고정 50k 토큰 상당(사람 한 번 부르는 값 — **열린 결정**, 아래) | 0 |

- 아낀 것은 보상에서 **T 를 0 으로 두고 LLM 의 T 와 비교**하는 꼴로 들어간다(같은 경계에서 LLM 을 골랐다면 쓴 토큰).
- **금지된 정답(학습 라벨로도 평가 라벨로도 안 쓴다):**
  1. **P1 의 재생 대리** — "그 사이 저장소를 바꾸는 도구 호출이 있었나". 지난 재생에서 틀림 18 중 17 이 이 대리의 거짓 양성이었다.
     P1 의 V · W 는 진짜 상태 해시로만.
  2. **P3 의 정의상 일치** — "기다리는 턴이 연달아 있으면 맞음". 이것은 아낀 턴 수를 센 것이지 맞음이 아니다. P3 의 W 는 위의
     '중간 보고' 조건으로만.
  3. **지난 오프라인 재생의 P2 라벨** — `merged == true` 를 확인하지 않고 호출 모양만 봤다. 쓰지 않는다.
  4. 모형 자신의 말("머지했습니다", "끝났습니다").
  기록기는 줄마다 `src=hook` 을 적고, 보상 셈은 `src=hook` 이 아닌 줄을 근거로 받으면 **예외로 멈춘다**(검사로 붙든다).

보상 민감도(보고만): λ × {0.5, 2}, μ × {0.5, 2} 의 네 판에서 결정이 같은지 적는다. 다르면 §9 의 무효화에 걸린다.

## 5. 정책 — XCS (단일 걸음, 맥락 밴딧)

- 표준 XCS(Wilson 1995 · Butz & Wilson 2001 의 알고리즘 기술 — 인용은 선행조사가 확인하기 전까지 `[출처:기억]`).
- 한 경계 = 한 문제. 반사실 보상이 가림 안의 **모든** 행동에 있으므로 맞춤 집합의 모든 행동을 갱신한다(진화효과 실험의 '지도형 전체 갱신' 과 같다).
- 고정 매개변수: N = 400 · β = 0.2 · α = 0.1 · ε₀ = 0.01 · ν = 5 · θ_GA = 25 · χ = 0.8 · 변이 0.04 · θ_del = 20 · δ = 0.1 ·
  θ_sub = 20 · P# = 0.33 · θ_mna = 가림 안 행동 수 · θ_exp(실행 때 신뢰) = 20 · 학습 epoch 30 · 씨앗 1..5.
- 실행: 예측 배열 argmax, 단 §3 의 '기본은 올림'. 씨앗 다섯의 **다수결 행동**을 경계의 행동으로(셋 이상이 같지 않으면 LLM).
- 매개변수를 고르려고 시험을 보지 않는다. 학습 세션 안에서 세션 단위로 떼어 둔 20% 로 θ_exp 만 {10, 20, 40} 에서 고를 수 있다 — 그 밖은 위 값 그대로.

## 6. 자료 · 봉인 가르기

- **자료**: 사용자의 실사용 Claude Code 세션에 그림자 기록기(§2 · §4 의 필드를 더한 판)를 건 뒤 생긴 세션만. 중첩 실행(`claude -p` 를
  이 세션 안에서 띄워 session_id 를 물려받은 것)은 뺀다. `그림자_실제.json` 의 다섯 세션은 이미 봤으므로 시험에 안 넣는다.
- **세션 단위로만 가른다. 턴 단위로 가르지 않는다**(같은 세션의 이웃 경계는 거의 같은 특징 · 같은 일이다).
  `sha256("walp-xcs-v1:" + session_id)` 의 첫 16진 자리가 0~4 면 **봉인 시험**(≈31%), 그 밖은 학습. session_id 는 Claude Code 가
  무작위로 주므로 누구도 고를 수 없다. 이 규칙은 기록 시작 **전에** 정해진다(지금).
- **보기 전에 볼 수 있는 것**: 세션 수 · 경계 수 · 레포 수 · 일의 종류(VV 축 A) · 가림별 경계 수. **보상 · 정책 출력은 학습 쪽에서도
  시험 쪽에서도, 최소 자료가 찰 때까지 안 본다**(학습 쪽 개발은 기록기 배선 검사 · 가짜 자료로만).
- 시험은 **한 번만** 연다. 연 뒤 그 세션들은 학습 쪽으로 옮기고, 다음 결정은 새 세션으로.

### 최소 자료 — 못 채우면 "잴 만큼 안 나왔다"

| 쪽 | 최소 |
|---|---|
| 학습 | 세션 ≥ 20 · 레포 ≥ 3 |
| 시험 | 세션 ≥ 10 · 레포 ≥ 3 · 일의 종류 ≥ 2 · **행동마다 가림이 열린 경계 ≥ 10** |
| 마감 | 위가 다 차거나 **2026-12-31** 중 먼저 |

마감에 못 채우면: 시험을 열지 않고(또는 연 것만으로) **"잴 만큼 안 나왔다"** 로 적는다. 결정은 없음, 아무것도 안 켠다, 모인 수만
적는다. 행동별로 따로 — P3 는 찼고 P1 은 못 찼으면 P1 칸에만 그렇게 적는다.

**미리 적는 산수**: 아래 규칙 R3(잘못 자동 ≤ 1% Wilson 95% 위 한계)는 **틀림 0 이어도 제안 ≥ 381** 이어야 선다
(틀림 1 → 563, 2 → 726, 3 → 878). 제안 10 개면 틀림 0 이어도 위 한계 27.8% 다. 지난 사용에서 P1 은 세션 하나에 27 개였다 —
**R3 는 이 실험의 규모에서 대개 안 설 것이다.** 그것을 알고 등록한다: 그때는 "켜기 후보 아님, 잘못 자동이 드물다는 것을 보일
만큼 안 나왔다" 로 적는다. 기준을 낮추지 않는다.

## 7. 기준선(조건)

| 이름 | 무엇 |
|---|---|
| B0 늘 LLM | 모든 경계에서 LLM. 아낌 0 · 잘못 0 |
| B1 손 규칙 | `execpolicy.py`(a2be5b9) 의 방아쇠 그대로: P1 = 같은 말 + Stop 때 상태 같음(진짜 해시) · P2 = `git commit` 이 든 턴 · P3 = 기다리는 명령이 든 턴(연쇄의 첫 것) · 그 밖 LLM. **이것이 지금의 챔피언**(실사용에서는 꺼져 있다) |
| B-가림 | 가림이 열리면 그 행동(여럿이면 P3 > P2 > P1 순), 아니면 LLM — **가림이 일을 다 하는가** |
| X0 덮기만 | §5 의 XCS, θ_GA = ∞(덮기 · 삭제만), 같은 N · epoch · 씨앗 |
| XG XCS+GA | §5 그대로 |
| (대조) XG-섞음 | 학습 쪽 보상을 **세션 안에서 경계끼리 무작위로 섞어** 기른 XG — 누수 · 우연 검사. B0 근처로 떨어져야 한다 |

## 8. 가설 · 결정 규칙 — 열기 전에 적는다

지표는 봉인 시험에서, 경계의 보상 합을 **세션별로** 모은다(경계는 세션 안에서 독립이 아니다).

- **H1 손 규칙을 이긴다**: 세션별 Σr(XG) > Σr(B1) — 세션 단위 단측 부호검정
- **H2 GA 가 일한다**: 세션별 Σr(XG) > Σr(X0), 그리고 씨앗 다섯 중 넷 이상에서 XG 의 시험 보상 합 > X0
- **H3 늘 LLM 을 이긴다**: 세션별 Σr(XG) > Σr(B0)
- Holm 으로 셋을 묶어 α = 0.05.

**행동(P1 · P2 · P3)마다** XG 가 그 행동을 '켜기 후보'(V2 봉인 A/B 로 넘어갈 자격)로 올리려면 **다 참**이어야 한다:

| | 기준 |
|---|---|
| R1 | 그 행동의 제안(XG 가 그 행동을 고른 경계) ≥ 10 |
| R2 | 일치율(V = 1 인 제안 / 제안) ≥ 90% |
| R3 | 잘못 자동(W = 1 / 제안) 의 Wilson 95% 위 한계 ≤ 1% |
| R4 | 허가 없는 바깥 동작 0(그림자이므로 '바깥 동작을 자동으로 하자는 제안' 0 — §0-3 위반을 세는 검사) |
| R5 | H1 이 섰다, 그리고 그 행동의 R2 · R3 가 B1 의 같은 행동보다 나쁘지 않다(일치율 ≥ · 잘못 자동 ≤) |

- H2 가 안 서면: "GA 가 아무것도 안 했다" 로 적고, 후보가 된다면 **X0(더 단순한 것)** 를 후보로 올린다. GA 를 이유로 말하지 않는다.
- H1 이 안 서면: 아무것도 후보가 아니다. B1 이 그대로 챔피언(실사용에서는 계속 꺼짐).
- 이 사전등록의 어떤 결과도 **무엇을 켜지 않는다.** 최대치는 'V2 후보' 다. 켜기는 VV.md §5 의 V2 · V3 가 정한다. P1 은 V2 에서도 따로(§0-1).

**래칫**: 챔피언은 B1. 도전자(XG 또는 X0)는 새로 연 봉인 시험에서 H1 + R1~R5 를 다 지날 때만 챔피언이 된다. 다음 교체는
새 세션으로만(연 시험은 학습으로 옮긴다). 안전 지표(R3 · R4)가 챔피언보다 나빠지면 보상이 높아도 바꾸지 않는다.

## 11. 이 실험이 **못** 말하는 것

- 그림자다 — 켰을 때 모형의 다음 행동이 바뀌는 효과(요약 한 줄이 맥락에 들어가 다음 턴이 달라짐)는 안 쟀다. 그것은 V2 다.
- 사용자 한 사람의 세션이다. 다른 사람 · 다른 일의 섞임에서 같을지 모른다.
- P1 의 V 는 상태로만 본다 — 상태가 같아도 답의 내용이 달라야 했을 수 있다(`PREREG_그림자.md` 와 같은 한계).
- P3 의 '중간 보고' 판정은 사람이 그 보고를 원했는지 모른다 — 보고가 있었다는 것만 본다.
- 보상의 반사실은 "LLM 이 실제로 간 길" 에서만 매겨진다. LLM 이 그 경계에서 틀린 길로 갔다면 정책의 반사실도 그 위에 선다.

## 열린 결정 — 사용자가 정할 것(확정 전에)

1. **'사람에게 묻기' 의 값**(지금 50k 토큰 상당, 근거 없음). 사람의 시간을 토큰으로 바꾸는 값이라 내가 정할 수 없다
2. **λ · μ** 의 크기(지금 μ = 10, λ = 1e-7/토큰). μ ≫ λ 만 요구받았다 — 비율 ≈ 240 턴이 맞는가
3. **R3 를 381 제안 규모로 그대로 둘 것인가** — 그러면 이 실험은 대개 '후보 아님' 으로 끝난다(낮추자는 것이 아니라, 그걸 알고 시작하는지)
4. **P2 의 로컬 커밋도 자동이 아니게** 할 것인가(지금은 커밋 · 깨끗한 워크트리 검사까지가 '켰다면' 의 몫)
5. 마감 2026-12-31 과 최소 레포 3 — 그만큼 여러 레포에서 쓰는가
