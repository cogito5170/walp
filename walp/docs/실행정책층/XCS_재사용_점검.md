## 0. 한 줄 결론

- **`walp/xcs.py` 자체는 언어와 무관하다** — 조건은 `{0,1,#}` 글자열, 입력은 아무 `0/1` 글자열, 행동은 `0..n_actions-1` 정수다.
  실행 정책에 그대로 쓸 수 있다. 언어에 묶인 것은 그 **위**(`dialog.py` 의 특징 · 관문 · 래칫, `behavior.py` 의 센서)다.
- **배울 자료는 이 컨테이너에 없다.** 커밋된 것은 **집계 수**(정책마다 제안 · 맞음 · 틀림)뿐이고, 결정 지점별 (상태 비트, 정답 행동)
  행은 한 줄도 없다. 1,485 턴 추적과 실제 그림자 원장(`~/.walp/shadow.jsonl`)은 **여기 없다.**
- 있다 해도 양이 모자란다: 커밋된 재생 수로 셈한 라벨 있는 결정 지점은 정책마다 **27 · 129 · 79**(맞음 9 · 15 · 79)이고,
  잡담 XCS 는 **2,368 문장**(× 60 epoch)으로 길렀다.

## 1. XCS 의 생김새 — 파일:줄

C++ 학습기(`walp/src/learner.cpp`)는 **XCS 가 아니다.** 로봇 탐색 정책 매개변수(`k_confirm` · `lambda_g` …)의 후보를 만드는 변이 생성기다
(`learner.cpp:1-6` 머리말 "정책 학습 — 후보만 만든다", `:12-30` `default_params_raw`, `:72-77` `CH_*` 변경 종류). XCS 는 파이썬
`walp/xcs.py` 하나뿐이다(표준 라이브러리만, `xcs.py:1-4`).

| 항목 | 어디 | 내용 |
|---|---|---|
| 분류자 표현 | `xcs.py:40-50` (`Cl`) | `cond: str`(삼진 `0/1/#`), `act: int`, `p`(예측 보상) · `eps`(오차) · `F`(적합도) · `exp` · `ts` · `as_` · `num`(수량) |
| 맞춤 | `xcs.py:52-53` | `all(c == "#" or c == b for c, b in zip(self.cond, x))` — **삼진**. 실수 · 구간 조건은 없다 |
| 일반성 | `xcs.py:55-58` | `#` 수로 비교(포섭용) |
| 행동 집합 | `xcs.py:61-64`, `:76-86` | `n_actions` 는 **생성 때 고정**. 덮기는 맞춤 집합에 없는 행동마다 규칙 하나를 넣는다 — 맞춤 집합은 늘 모든 행동을 담는다 |
| 덮기 | `xcs.py:79-80` | 비트마다 `p_hash`(입력 1 비트엔 `p_hash_one` 선택) 확률로 `#` |
| 예측 배열 | `xcs.py:88-94` | 적합도 가중 평균 `Σ p·F / Σ F` |
| 이용(추론) | `xcs.py:96-103` `predict` | 집단을 안 바꾼다. 맞는 규칙이 없으면 `(-1, [])` |
| 갱신 | `xcs.py:105-117` `_update` | Widrow-Hoff(MAM `max(β, 1/exp)`), 정확도 `κ`(ε0 · α · ν), 상대 정확도로 `F` |
| GA | `xcs.py:146-184` `_ga` | 행동 집합 평균 `ts` 가 `theta_ga` 넘으면, 적합도 룰렛 2 부모, 두 점 교차(`chi`), 틈새 변이(`#`↔입력 비트, `mu`), 행동 변이(`mu`) |
| 포섭 | `xcs.py:177-181` | **GA 포섭만** — 부모가 `exp>theta_sub` · `eps<eps0` · 더 일반이면 자식을 삼킨다. 행동 집합 포섭은 없다 |
| 삽입 · 삭제 | `xcs.py:119-144` | 같은 (조건, 행동)이면 `num+1`. 삭제는 `as_·num` 표 + 적합도 낮은 노련 규칙 가중(Butz-Wilson 꼴) |
| 보상 경로 4 가지 | `xcs.py:187-236` | `step_label`(탐색=무작위 행동, `:192-193`) · `step_label_full`(라벨 → 모든 행동 갱신, UCS 꼴) · `step_bandit`(좋음/나쁨) · `step_reward`(수치 밴딧, 0..1000) · `step_rewards`(**행동마다 반사실 보상을 다 앎**) |
| 결정성 | `xcs.py:10`, `:69-70` | 난수는 `random.Random(seed)` 하나. 같은 씨앗 · 같은 표본 순서면 같은 집단 |
| 저장 | `xcs.py:239-251` | `{"n_actions", "params", "seed", "t", "pop":[Cl…]}` JSON. **난수 상태는 안 저장한다**(`from_json` 은 `seed` 로 새 RNG, `:245`) |

## 4. 재사용의 위험

1. **조건 길이 불일치가 조용히 지나간다.** `matches` 가 `zip` 이라(`xcs.py:53`) 입력이 조건보다 길면 남는 비트를 **안 보고**,
   짧으면 조건의 꼬리를 안 본다. 특징을 하나 더하면 기존 집단이 오류 없이 틀린 답을 낸다. 적재 때 길이 검사를 따로 둬야 한다.
2. **행동 수는 생성 때 고정**(`xcs.py:63`). 행동 번호 = 리스트 위치(`dialog.ACTS.index`)라 행동을 끼워 넣으면 저장된 집단의 뜻이 바뀐다.
   `n_actions` 를 늘리면 덮기(`:76`)가 새 행동 규칙을 채우기는 하지만 문서화된 길은 아니다. 행동은 **맨 뒤에만** 덧붙여야 한다.
3. **덮기는 늘 모든 행동을 채운다**(`xcs.py:76-86`). 처음 보는 상태에서도 `predict` 가 `-1` 대신 초기 예측(`p_i=10`)의 행동을 낼 수 있다 →
   확신 문턱(`CONF` 꼴) 없이 쓰면 "기본은 올림"(설계 §5-3)이 깨진다. 단, `predict` 자체는 덮기를 안 하므로(`:98`) 학습 뒤 처음 보는 상태는 `-1`.
4. **`step_label` 의 탐색은 무작위 행동이다**(`xcs.py:192-193`). 실행 정책에서 이것을 온라인으로 부르면 무작위로 밀기/머지가 날 수 있다.
   **오프라인 `step_rewards` · 그림자 `step_reward` 만** 써야 한다(설계 §5-1 불변식).
5. **언어 결합**: `dialog.특징` · `입력` · `어휘기르기` · `관문` · `교체할까`, `behavior.센서` · `불확실비트` 는 글 · `ACTS` · 손 규칙을 읽는다.
   `behavior.py` 를 import 하면 `dialog` 가 통째로 딸려 온다(`behavior.py:20`).
6. **C++ 빌드**: XCS 는 순수 파이썬이라 필요 없다. 그러나 대화 특징의 파서 비트는 `walp_cli parse`(`front.py:52-69`)를 부르고, 빌드가
   안 돼 있으면 `{"error"}` 가 와서 파서 비트가 **조용히 0** 이 된다(`dialog.py:94-103` 의 `r.get` 들). 실행 정책이 대화 특징을 빌려 쓰면 같은 함정.
   `learner.cpp` 는 XCS 가 아니므로 재사용 대상이 아니다.
7. **결정성 · 씨앗**: 같은 씨앗 · 같은 순서면 같은 집단(탐침 확인). 그러나 (a) 난수 상태를 저장하지 않아 `from_json` 뒤 이어 배우면
   한 번에 배운 것과 다른 집단이 된다(`xcs.py:245`), (b) 배포본은 씨앗 하나(`front_model.json` seed 1)라 씨앗 흔들림을 안 쟀다 —
   적은 자료에서 흔들림이 크다(탐침 n=16: 0.45 ↔ 0.74). 사전등록에 씨앗 여러 개를 넣어야 한다.
8. **집단 포화**: 배포 L0 는 1,581/1,600 매크로 — `PREREG_행동기반.md:86` 이 "1599/1600 포화로 규칙을 못 굳혔다" 고 적은 바로 그 꼴이다.
   행동이 6 개로 늘고 특징이 섞이면 `N` 을 따로 골라야 한다.
9. **속도**: `_match` · `_delete` 가 걸음마다 집단 전체를 훑는다(`xcs.py:74`, `:128-144`). 턴 경계 훅에서 추론(`predict`)만 하면 괜찮지만,
   훅 안에서 학습하면 지연이 생긴다. 학습은 오프라인으로.
10. **보상 척도**: XCS 는 0..`reward`(1000) 를 가정한다(`ε0=10` 이 그 척도 기준, `xcs.py:24`, `:37`). 토큰 비용(수십만)을 그대로 넣으면 정확도 계산이 무너진다 —
    `behavior.보상` 처럼 [−1, 1] 효용을 0..1000 으로 사상해야 한다.
11. **선행연구 확인 범위**: `선행조사.md:26`, `:35` — "XCS 정책 + LLM 에이전트" 직접 겹침은 두 번 찾아 못 찾았고 GECCO · IWLCS · Springer/ACM DL 은 **아직 안 봤다.**

## 5. 권하는 순서(짓기 전에)

1. 원 추적에서 **결정 지점별 행**(상태 비트 + 사전등록 정의에 따른 행동별 반사실 보상)을 뽑는 추출기를 먼저 짓고, 그것을 커밋된 집계 수와 맞춰 본다
   (독립 대조: 행을 합치면 `그림자_재생_주세션.json` 의 수가 나와야 한다).
2. 실제 그림자 원장을 제안 ≥10 까지 쌓는다(사전등록 결정 규칙). 그 전에는 XCS 를 길러도 관문을 잴 표본이 없다.
3. 처음 학습 대상은 6 행동이 아니라 **2 행동(자동/올림)** — `behavior.L1기르기` 의 꼴. 자료가 적을 때 행동이 적어야 덮기 · GA 가 굳는다.
4. 수를 말하기 전에 사소한 설명을 잰다: 다수 행동(늘 LLM 턴) 기준선, 씨앗 여럿, P3 처럼 정의상 참인 라벨 빼기.
