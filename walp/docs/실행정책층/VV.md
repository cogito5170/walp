# 실행 정책층 V&V — 모든 저장소에서 "토큰을 줄였다" 를 어떻게 보이나

**Verification(바르게 지었나)** = 명세(안전 불변식 · 셈)를 지키나. **Validation(바른 것을 지었나)** = 실제 일에서 성공을 잃지 않고
토큰을 줄이나. 둘을 따로 재고, 하나가 초록이라고 다른 하나를 말하지 않는다.

## 1. 요구사항과 추적표

| id | 요구 | 종류 | 어떻게 재나 | 통과 기준 |
|---|---|---|---|---|
| R1 | 바깥 · 되돌릴 수 없는 동작을 허가 없이 하지 않는다 | 검증 | 위험 등급별 동작을 넣은 고장 주입 · 변이 검사(허가 표를 빼면 실패해야) | 0 회 |
| R2 | 자동 결과는 결정론적 확인을 지난다 | 검증 | 확인을 일부러 틀리게(검사 실패 · merged=false) 했을 때 LLM 으로 올라가나 | 전부 올라감 |
| R3 | 정책층 고장은 아무것도 막지 않는다 | 검증 | 체계 파일 없음 · 입력 깨짐 · 시간 초과 주입 | 전부 통과(그대로 감) |
| R4 | 토큰 셈이 맞다 | 검증 | 추적 셈 vs cost-state(다른 길) · 손계산 작은 추적 | 차 ≤ 5% · 손계산 일치 |
| R5 | 재생이 결정적이다 | 검증 | 같은 상태에서 매크로 두 번 → 같은 결과 | 일치 |
| R6 | 성공을 잃지 않는다 | 확인 | 봉인 과제 A/B, 성공률 | 비열등(−2%p 여유, 단측 95%) |
| R7 | 토큰을 줄인다 | 확인 | **성공한 과제당** 토큰(새 입력 · 캐시 · 출력 나눠) | 차의 단측 95% 상한 < 0 |
| R8 | 돈을 줄인다 | 확인 | 과제당 $ — **실패 런 포함** | 차의 상한 < 0 |
| R9 | 잘못 자동 실행이 드물다 | 확인 | 정책이 LLM 을 건너뛴 걸음 중 틀린 것 | ≤ 1% (Wilson 위 한계) · 바깥 동작은 0 |
| R10 | 어느 칸에서도 나빠지지 않는다 | 확인 | 아래 과제 칸마다 R6 · R7 | 칸마다 보고, 나빠진 칸은 그 칸에서 끈다 |

## 2. 환경이 맡아야 할 과제 — "모든 경우" 를 칸으로

한 수(평균 절감)는 가장 유리한 구석에서 나온다(잡담층 v1 이 그랬다). 그래서 과제를 **다섯 축의 칸**으로 나누고 칸마다 보고한다.

| 축 | 칸 | 왜 |
|---|---|---|
| **A. 일의 종류** | 버그 고치기(재현 검사 있음) · 명세로 기능 · 검사 짓기 · 리팩터/이관/의존성 올리기 · 문서 · 읽기만(질의 · 코드 길 찾기) · 빌드/CI 수리 · **운영 루틴**(커밋 · PR · 머지 · 배포 확인) · **긴 작업 돌리고 기다리기**(실험 · 배치) · 대화/잡담 · 외부 도구(MCP) 질의 | 이 세션에서 루틴과 기다리기가 토큰의 40% 넘게 먹었다 — 선행 벤치마크(SWE-bench 류)에는 이 칸이 없다 |
| **B. 반복 구조** | 똑같은 되풀이 · 값만 다른 되풀이 · 같은 레포 새 일 · 새 레포 | 재사용이 되느냐를 정하는 축. **칸마다 따로** 보고한다 |
| **C. 길이** | 짧음(≤5 턴) · 중간 · 긺(>30 턴) | 맥락 눈덩이는 긴 일의 문제 |
| **D. 확인 가능성** | 오라클 검사 있음 · 끝상태 판정(API · 심판) · 사람만 | 결정론적 확인 게이트는 앞의 둘에만 선다 |
| **E. 위험** | 읽기 · 로컬 쓰기 · 바깥(push · PR · 망) · 되돌릴 수 없음 | R1 · R9 |

### 과제는 어디서 오나 — 우리 저장소들의 실제 이력에서

- **이력 되짚기**: SE · walp · worldplan · worldTrip · gentleMonster 의 커밋마다 "부모 커밋에서 출발해 이 커밋 메시지를 과제로,
  그 커밋의 검사 통과를 오라클로" — 레포를 가로지르는, 실제 섞임의 코딩 과제(A 의 앞쪽 칸 · D=오라클)
- **루틴 대본**: 커밋 → 검사 → PR → 머지 → 확인, 긴 실험 기다리기, 밀기 거절 고치기 — 임시 저장소 · bare 원격으로 지어 끝상태로 판정
- **봉인 대화 모음**: 잡담 · 섞인 말 · 질의 — 지금까지의 봉인 방식(독립 하위 에이전트가 쓰고 sha 를 먼저 커밋)
- 칸마다 최소 k 개(예: 5). 빈 칸이 있으면 "그 칸은 안 쟀다" 로 적는다

## 3. 조건(기준선)

그냥 에이전트 · 관찰 가리기(observation masking) · 프롬프트 캐시만 · 계획 캐시(APC 식) · **WALP 정책층** · WALP − 매크로(대조: 매크로가 하는 몫)

## 4. 단계 — 위험이 낮은 것부터

| 단계 | 무엇 | LLM 비용 | 무엇을 보이나 |
|---|---|---|---|
| **V0 추적 재생** | 기록된 세션들에 `walp.trace_stats` · 정책을 오프라인으로 대 본다 | 0 | 상한 — 이 세션만의 것인가 |
| V1 그림자 | 실사용에서 정책은 **제안만**, 실제 행동은 LLM. 둘의 일치율 | 0 추가 | 정책이 맞는가(행동 기준) |
| V2 봉인 A/B | 위 칸들의 봉인 과제, 조건 무작위 순서 · 3회 반복(런 간 분산) | 과제당 몇 $ | R6~R10 |
| V3 점진 켜기 | 통과한 칸만 켠다. 원장으로 감시, 나빠지면 그 칸을 끈다 | — | 실제 섞임에서의 수 |

## 5. 결정 규칙 — 열기 전에 적는다

R1 · R2 · R3 이 하나라도 실패하면 **켜지 않는다**(검증 실패는 확인 결과와 상관없다). 그다음 칸마다: R6 비열등 · R7 상한 < 0 ·
R9 ≤ 1% · 바깥 동작 무단 0 이면 그 칸에서 켠다.

## 6. 사소한 설명 — 재서 죽일 것

1. **절감이 캐시 가격 탓** — 토큰과 $ 를 둘 다(캐시 읽기는 싸다. 이 세션은 98.6% 가 캐시 읽기였다)
2. **쉬운 과제 쏠림** — 칸별 보고(R10)
3. **실패를 숨겨 아낀 것** — 성공당 토큰 · 실패 포함 $
4. **런 간 분산** — 3회 반복(선행: 같은 과제에서 최대 30× 차가 보고됨 [출처:조각])
5. **이미 있는 도구의 몫** — WALP − 매크로 대조, 관찰 가리기 기준선
6. **셈이 틀림** — R4(이 세션: 추적 611.0M vs cost-state 643.3M, 차 5.0%)

## 7. V0 — 지금 된 것

- `walp/trace_stats.py`: 세션 JSONL → 집계(글은 안 낸다). 검사 `tests/test_trace_stats.py` — 손으로 지은 추적과 손계산이 같다 ·
  비밀 글이 밖으로 안 나간다 · 스트림으로 나뉜 같은 턴을 한 번만 센다
- 주 세션(1,454 턴): 루틴 40~45% · 연쇄 덧턴 13.8% · stop 훅 9.3% · 턴당 맥락 평균 419k (`설계.md` §1, `추적_이세션.json`)
- 하위 에이전트 6 개(조사 · 쓰기, `--sidechain`): 루틴 **0.7%** · 연쇄 덧턴 0% · 읽기가 대부분 · 턴당 맥락 중앙 67k
- **V0 의 결론: 절감의 크기는 일의 종류에 달렸다.** 루틴 매크로(P2 · P3)는 운영이 많은 일에서만 값이 있다. 읽기가 많은 일에서는
  관찰 압축(P4)과 맥락 크기가 지렛대일 것이다 — 아직 상한을 안 쟀다. 둘 다 같은 사람 · 같은 날 · 같은 모형의 추적이다;
  다른 사용자 · 다른 레포의 추적이 아직 없다
