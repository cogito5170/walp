# WALP 실행 정책층 — 설계 (이 과제의 실행 추적에서 출발)

잡담 필터는 **어떤 말에 답할지** 를 골랐다. 실행 정책층은 에이전트 루프(계획 → LLM → 도구 → 결과 → LLM → 재계획 …)의
**턴 경계마다 다음 일을 누가 하나** 를 고른다 — LLM 턴인가, 이미 있는 결과 · 굳힌 매크로 · 결정론적 도구인가.
모든 저장소에서 쓴다(어느 레포의 코드에도 매이지 않는다).

## 1. 근거 — 이 세션의 추적 (`python3 -m walp.trace_stats`, 집계만: `추적_이세션.json`)

이 문서를 쓰기까지의 세션 하나(worldplan 앱 · Gemini/Claude · walp-front · 이 설계 요청까지):

| 잰 것 | 값 |
|---|---|
| 모형 턴 · 토큰 | 1,454 턴 · **611M 토큰**, 그중 **캐시 읽기 98.6%** · 비용 $230.78 |
| 턴당 맥락 | 평균 **419k** · 중앙 417k · 90% 688k |
| 독립 대조 | 같은 파일의 cost-state(다른 길로 센 합) 643.3M — 차 5.0%(하위 에이전트 · 압축 전 몫으로 본다) |

**첫째 결론: 비용 = 턴 수 × 그때의 맥락.** 한 걸음이 무엇을 했느냐보다 **턴이 하나 더 돌았느냐** 가 거의 전부다.
턴 하나를 없애면 평균 ~419k 토큰이 준다. 그러니 정책층의 일차 목표는 **턴을 없애는 것**, 이차가 턴에 실리는 것을 줄이는 것이다.

턴을 부른 것과 걸음 종류(종류는 그 턴의 첫 도구로 — 범주를 어떻게 나누느냐에 따라 수가 몇 %p 움직인다):

| 무엇 | 토큰 몫 | 읽는 법 |
|---|---|---|
| 루틴 걸음(git · PR·머지 · 기다리기 · 검사 돌리기) | **40~45%** (분류 방식 둘) | 결과가 미리 정해진 걸음 |
| 그중 **같은 루틴이 연달아** 돈 덧턴 | **13.8%** (181 턴) | 한 번(매크로 · 이벤트)이면 될 것을 여러 턴으로 |
| **stop 훅이 부른 턴** | **9.3%** (54 번 → 126 턴) | 상태가 안 바뀌었는데 같은 답을 매번 새로 지었다 |
| 답 쓰기(도구 없는 턴) | 9.5% | LLM 몫 |
| 고치기 · 읽기 | 각 ~20% | 대부분 LLM 몫. 같은 파일 거듭 읽기 · 셸 편집 연쇄는 줄일 여지 |

**두 번째 데이터가 첫 번째를 꺾었다.** 같은 세션의 하위 에이전트 추적 6 개(조사 · 봉인 모음 쓰기, 5~21 턴, 4.2M 토큰)에서는
루틴 몫이 **0.7%**, 연쇄 덧턴 **0%** 였고 읽기가 대부분이었다(턴당 맥락 중앙 67k). 즉 위 40~45% 는 **배포 · PR 이 잦은 이 세션의 일
섞임**에서 나온 것이지 에이전트 일반의 수가 아니다. 정책 P1~P3 의 값어치는 일의 종류에 달렸다 — 그래서 V&V 가 칸별(일의 종류)로 보고한다.

**사소한 설명을 미리 적는다.** 이 수는 (1) 세션 **하나**, (2) 내가 낸 일의 섞임(배포 · PR 이 잦았다)에서 나왔다.
(3) 위 몫들은 "그 턴을 통째로 없앨 수 있다" 고 가정한 **상한**이다. 다른 레포 · 다른 일에서 다시 재야 한다 — 그것이 V&V(`VV.md`)다.

## 2. 이 추적에서 바로 나온 정책 다섯 — 상한과 함께

| # | 정책 | 무엇을 없애나 | 이 세션의 상한 | 검증 수단 |
|---|---|---|---|---|
| P1 | **같은 상태면 같은 답 재사용** | 상태 해시(저장소 HEAD · 원격 · 작업 트리)가 직전 보고 때와 같으면 LLM 을 안 부르고 직전 결론을 다시 낸다 | stop 훅 턴 9.3% | 상태 해시가 같다는 것 자체 |
| P2 | **발행 매크로** | 커밋 → 깨끗한 워크트리 검사 → 밀기 → PR → 머지 → 조회로 머지 확인 을 도구 한 번으로 | 루틴 연쇄 덧턴 13.8% 의 git · PR 몫 | 검사 통과 · API `merged: true` — 하나라도 안 되면 멈추고 LLM 으로 |
| P3 | **기다리기 이벤트화** | `kill -0` 폴링 턴 대신 "끝나면 한 번 깨운다" | 기다리기 11.1% 의 대부분 | 프로세스 종료 · 로그 끝 줄 |
| P4 | **관찰 압축** | 검사 출력은 실패 이름 + 단언 차이만, 같은 파일 재읽기는 바뀐 줄만 | 턴 수가 아니라 맥락 증가를 줄인다(상한 미측정) | 압축 전 · 후 같은 결론(대조 실험) |
| P5 | **알려진 고침** | 결정론적 실패(예: 밀기 거절 → merge 후 다시, 깨끗한 워크트리에서만 실패 → git add 빠짐)에 정해진 수 | 미측정 | 고친 뒤 같은 검사 통과 |

P1~P3 은 결과를 **결정론적으로 확인**할 수 있어서 먼저다. 잡담층이 진 이유(확인할 길 없이 답했다)를 되풀이하지 않는다.

## 3. 어디에 붙나 — 두 자리

1. **곁(사이드카) — Claude Code · Gemini CLI 안에서.** 루프는 모형이 돈다. 정책층은 끼어들 수 있는 자리에서만 일한다:
   - `UserPromptSubmit` 훅 — 이미 있다(잡담). 같은 자리에서 P1(같은 상태 재사용)
   - **매크로를 MCP 도구로 내놓는다**(P2 · P3) — 모형이 한 번 부르면 정책층이 여러 걸음을 결정론적으로 돌고 **요약 한 줄**만 돌려준다
   - `PostToolUse` · `PreToolUse` 훅 — 관찰 압축(P4) · 위험 동작 확인. *훅이 도구 출력을 바꿀 수 있는 범위는 CLI 판마다 확인할 것*
2. **운전석 — 우리가 루프를 도는 곳**(worldplan 도우미 · `walp-front` 의 에이전트 모드). 걸음마다 정책층이 먼저 고르고, LLM 은
   필요한 걸음에서만 부른다. 결과 해석 · 재계획을 결정론적 심판으로 닫을 수 있는 곳이 여기다.

## 4. 정책 — XCS 로 배운다

- **상태(조건)**: 직전 걸음 종류 · 결과 판정(성공 / 실패 / 직전과 같은 결과) · 상태 해시가 바뀌었나 · 걸음 수 · 맥락 크기 ·
  레포 특징(언어 · 검사 명령 유무 · 원격 유무) · 다음 동작의 위험 등급(읽기 / 로컬 쓰기 / 바깥 · 되돌릴 수 없음)
- **행동**: `LLM 턴` · `매크로 k` · `직전 결과 재사용` · `관찰 압축` · `이벤트 기다리기` · `사람에게 묻기`
- **보상**: 성공(결정론적 검사 통과 · 사람이 고치지 않음) − λ·토큰 − μ·(잘못 자동 실행). μ ≫ λ
- **매크로는 추적에서 굳힌다**(Soar 의 chunking): 같은 구조로 k 번 이상 되풀이되고 매번 결정론적으로 성공한 걸음 열을 후보로,
  **그림자 모드**에서 제안 · LLM 실제 행동과의 일치율을 재고, 봉인 V&V 를 지나야 켠다
- 래칫 — 지금의 WALP 와 같다: 봉인 모음에서 이기고, 안전 지표가 나빠지지 않을 때만 바꾼다

## 5. 안전 불변식 (V&V 의 검증 대상)

1. **바깥 · 되돌릴 수 없는 동작은 허가된 매크로 안에서만** 자동으로 한다(밀기 · PR · 머지는 사용자가 저장소 규칙으로 허락한 곳에서만)
2. **자동으로 낸 결과는 결정론적 확인을 지나야** 결과가 된다. 확인이 없거나 실패하면 그 자리에서 멈추고 LLM 으로
3. **기본은 올림** — 확신이 없으면 LLM
4. 정책층이 터지면 **아무것도 막지 않는다**(사람의 말 · 모형의 행동을 잃는 쪽으로 틀리지 않는다)
5. 토큰 셈은 공급자 기록과 맞아야 한다(독립 대조 ≤ 5%)

## 6. 순서

1. 이 문서와 `선행조사.md` 를 사용자에게 먼저 보인다 (지금)
2. V0 — 여러 세션 추적에 `trace_stats` 를 돌려 P1~P3 상한이 이 세션만의 것인지 본다(LLM 0)
3. P1 · P2 · P3 을 짓는다 — 결정론적 확인이 있는 것부터
4. V1 그림자 → V2 봉인 A/B → V3 점진 켜기 (`VV.md`)
